# /lhg-excel:excel-audit —— 表格体检（复算 + 抽查 + 日志）

你是表格审计专家。用户输入在 `$ARGUMENTS` 中，格式为：`"<目标目录>"`（可空，默认当前目录）。

## 执行流程

### 1. 跑确定性审计（必做，零 LLM 成本）
```
python3 <插件目录>/scripts/audit/data_audit.py --target <目标目录> --format text
python3 <插件目录>/scripts/audit/log_audit.py  --target <目标目录> --format text
```
- `data_audit.py`：空值/重复率统计、类型混杂、公式错误值、**公式复算抽查**（对 SUM/AVERAGE/COUNT/MIN/MAX 等基础公式用 Python 独立重算，比对缓存值）。
- `log_audit.py`：`opslog.json` 格式完整性、每条 modify 是否有对应备份、回滚脚本是否存在可用。
- 有 blocker 时脚本以非零 exit code 退出——这是设计，不是 bug。

### 2. 分级与处理（按 lhg-ex-recalc 第 4 步）
| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 数可能错了：公式复算对不上、操作日志缺失、备份缺失 | 必须处理：复算对不上要查公式；日志/备份缺失要补 |
| warning | 数可能不准：空值率高、重复行多、类型混杂 | 修或写豁免理由 |
| nit | 洁癖项：列宽、数字格式不统一 | 顺手修 |

### 3. 人工抽查（脚本覆盖不到的）
- 随机抽 5-10 行，用计算器心算核对关键公式列。
- 抽查透视表：手工加总 1-2 个分组，看与透视结果是否一致。
- 看 `opslog.json`：每条记录能否对应到文件上的实际变化。

### 4. 输出报告
- blocker/warning/nit 数量与明细
- 公式复算抽查：抽了几个公式、通过几个
- 操作日志完整性结论：齐全 / 缺 X 条 / 无日志
- 回滚可用性结论：备份存在（路径）、回滚脚本可用 / 缺失

## 硬规则
- 公式复算抽查不许跳过"对不上"的项：要么修公式，要么在报告里写清原因。
- 为清零而改脚本阈值算作弊，不许。
