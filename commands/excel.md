# /lhg-excel:excel —— 杂乱表格 → 汇报版 xlsx 一条龙

你是表格数据专家。用户输入在 `$ARGUMENTS` 中，格式为：`"<表格文件路径>" [--report-only]`。

## 信任铁律（先读，再开工）

1. **改任何数据前先备份**：插件 hook 会在处理 xlsx 前自动备份原文件到同目录 `.bak/`（可用 `LHG_EXCEL_BACKUP_OFF=1` 关闭）。hook 没跑起来时，你必须**手动先复制一份原文件**再动手。
2. **每个数据变更都要记操作日志**：按 skill `lhg-ex-opslog` 的格式写 `opslog.json`（时间/操作/文件/行列范围/变更前后摘要），并生成 `rollback.sh`（或 `ROLLBACK.md`）说明如何回滚。
3. **不许悄悄改数**：清洗的每一步（删了多少重复行、填了几个空值、改了什么类型）都要在交付报告里给用户看数字。
4. **公式不许手算覆盖**：含公式的单元格只改公式本身，不许把公式替换成手算的静态值（除非用户明确要求）。

## 执行流程

### Phase 0：诊断（加载 lhg-ex-clean 第 2 步）
1. 确认文件存在、可读；`.xls` 老格式先转 `.xlsx`（转完校验行列数一致）。
2. 读表头与样本行：列数、行数、每列类型猜测、空值率、重复行率。
3. 跑确定性审计：`python3 <插件目录>/scripts/audit/data_audit.py --target <文件所在目录> --format text`，把 blocker/warning 记下来。
4. 给用户一份**诊断卡**：行列规模、主要脏数据问题清单、预计清洗动作。**用户确认后再动手改。**

### Phase 1：清洗（lhg-ex-clean 第 3-5 步）
1. 按诊断卡逐项清洗：去重 → 类型统一 → 空值处理 → 去除 junk 行（合并单元格拆出的空行、合计行混入明细等）。
2. 每做完一步，往 `opslog.json` 追加一条记录（含变更前后行数/示例）。
3. 洗完重跑 `data_audit.py`，确认 blocker 清零。

### Phase 2：透视与图表（lhg-ex-pivot）
1. 问用户要什么视角（不问超过 2 个问题，给默认推荐）：按哪个字段分组、聚合什么指标。
2. 生成透视表（新 sheet `透视_xxx`），再生成 1-3 张图表（新 sheet `图表_xxx` 或嵌入透视 sheet 旁）。
3. 图表三要素自查：标题说人话、坐标轴有单位、数据标签不遮挡。

### Phase 3：汇报版封装
1. 输出文件命名：`<原名>_汇报版_YYYYMMDD.xlsx`，原文件不动。
2. 汇报版结构：`README`（说明页：数据来源、清洗摘要、口径说明）→ `清洗后明细` → `透视_xxx` → `图表_xxx`。
3. 冻结首行、自动列宽、数字格式统一（金额千分位、百分比 1 位小数）。

### Phase 4：交付
给用户一份交付报告：
- 清洗动作清单（每步：动作、影响行数、依据）
- 透视结论（一句话说出数据讲了什么故事）
- 审计结果（blocker/warning 数量与处理）
- 回滚方式（备份文件路径 + `rollback.sh` 位置）
- `opslog.json` 路径（所有变更可查）

`--report-only`：只做诊断卡 + 清洗方案，不实际改文件。

## 硬规则
- 没备份就改原文件 → 停下来先备份。
- 清洗动作没记日志 → 补记后再继续。
- 用户没确认诊断卡就动手 → 先给诊断卡。
- 大文件（>5 万行）先提醒性能预期（见 README FAQ），建议分块或先抽样确认口径。
