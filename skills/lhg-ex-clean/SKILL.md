# lhg-ex-clean：表格数据清洗五步法

> 目标：把"凭感觉洗表"变成固定流程。核心纪律：**先诊断后动手，先备份后改数，每个动作记日志**。
> 适用对象：从业务系统导出的、手工维护的、合并多份来源的"杂乱表格"（xlsx / xls / CSV）。
> 不适用：数据库直连取数、实时 BI 看板——那是 lhg-sql / lhg-dashboard 的地盘。

## 1. 何时使用

- 用户丢给你一个表格说"帮我整理一下" → 全流程
- 只想知道表有多脏、暂不动手 → 只跑第 2 步（诊断）
- 表已经洗过一轮，想复查 → 跑第 6 步（复查）+ 插件审计脚本

## 2. 第一步：诊断（动手前必做）

用你所在平台读取文件的能力，先回答这 7 个问题，输出"诊断卡"给用户确认：

1. **规模**：多少行、多少列、几个 sheet？（>5 万行先提示性能预期）
2. **表头**：第一行是表头吗？有没有合并单元格表头、双层表头、表头上方还有标题行？
3. **空值**：每列空值率（空值率 >30% 的列标出来问用户：删列还是保留？）
4. **重复**：整行完全重复的有多少？主键（如订单号、工号）重复的有多少？
5. **类型混杂**：同一列里既有数字又有文本的有几列？（典型：金额列里混着"—""待定"）
6. **公式**：哪些列是公式？公式引用的范围对不对？（清洗不许破坏公式）
7. **junk**：表头上方/数据中间/末尾有没有标题行、空行、"合计"行混入？

诊断卡模板：

```
文件：xxx.xlsx（1.2 万行 × 18 列，1 个 sheet）
- 表头：第 3 行才是真表头，上方 2 行是标题（需删除）
- 空值：电话列空值率 41%（建议保留并标注）、金额列空值率 2%
- 重复：整行重复 37 行；订单号重复 12 个（需人工定）
- 类型混杂：金额列有 23 个"待定"文本；日期列有 3 种格式
- 公式：F 列=单价*数量（保留公式不碰）
- 预计动作：删 37 行、转 2 列类型、统一日期格式
```

**诊断卡未经用户确认，不许动手。**

## 3. 第二步：去重

顺序：先整行完全重复 → 再主键重复。

- 整行完全重复：保留首次出现，其余删除。记日志：`去重：删除 37 行整行重复`。
- 主键重复（如订单号）：**不许自动删**。把重复的主键及整行列出来，让用户决定留哪条（通常留最新/最全的一条）。
- 近似重复（姓名同音、公司名差一个字）：列出来人工定，不许用模糊匹配自动合并。

## 4. 第三步：类型统一

逐列处理，原则是"让机器能算，让人不误读"：

| 列类型 | 统一动作 |
|---|---|
| 数字 | 文本型数字转数值；千分位/货币符号去掉只留数值（格式用单元格格式表现）；"—""待定"等先标出问用户 |
| 日期 | 统一为 `YYYY-MM-DD`；识别 3 种常见坑：`2026/1/5`、`2026-01-05`、Excel 序列号、`1月5日`无年份（补当年并标注） |
| 枚举 | 是/否、男/女、已完成/未完成：统一写法，全表一致；列出所有 distinct 值给用户看一遍 |
| 文本 | 去首尾空格、全角转半角（数字/字母）、统一换行符 |

**红线**：类型转换失败的值不许静默丢弃——转成文本保留原值并标黄，记日志。

## 5. 第四步：空值处理

先统计，后动作，口径必须用户确认：

- 数值列：**默认不填 0**（填 0 会扭曲求和与均值）。除非用户明确说"空就是 0"。
- 文本列：留空，不填"无"/"空"（这些假值以后会污染筛选）。
- 关键列（如金额、日期）空值：列出来让用户补或决定删除整行。
- 填充动作记日志：`空值：金额列 23 个空值按用户口径填 0`。

## 6. 第五步：junk 行清理

- 表头上方的标题行：删除（标题信息记到 README 说明页）。
- 数据中间的空行：删除。
- 末尾"合计/总计"行：移到单独的汇总区或删除（记日志），不许留在明细里参与透视。
- 合并单元格拆出的碎片行：按上下文合并或删除，逐行确认。

## 7. 第六步：复查（清洗完必做）

1. 行数对账：`清洗后行数 = 原行数 - 删除行数`，对不上就查。
2. 跑插件审计脚本 `scripts/audit/data_audit.py`，blocker 清零。
3. 抽查 10 行：肉眼看类型、格式、公式是否正常。
4. 确认 `opslog.json` 每条记录都能对应到实际变化。

## 8. 常见脏数据模式速查表

| # | 症状 | 通常原因 | 处理 |
|---|---|---|---|
| 1 | 表头有合并单元格 | 手工排版 | 取消合并，向下/向右填充表头 |
| 2 | 同一列出现 3 种日期格式 | 多人维护 | 统一 `YYYY-MM-DD`，无年份的补当年并标注 |
| 3 | 金额列有"—""待定" | 业务未定 | 先标出问用户，不许当 0 |
| 4 | 数字存成文本（左上角绿三角） | 系统导出 | 整列转数值，转失败标黄保留 |
| 5 | 电话/身份证号变成科学计数法 | Excel 自动转换 | 转文本，补全被吃掉的前导 0 |
| 6 | 末尾"合计"行混入明细 | 手工汇总 | 移出或删除，不许参与透视 |
| 7 | 空行/空列穿插 | 删除行不彻底 | 整行/整列删除 |
| 8 | 全角数字字母 | 中文输入法 | 全角转半角 |
| 9 | 首尾空格导致匹配失败 | 复制粘贴 | 去首尾空格（VLOOKUP 前必做） |
| 10 | .xls 老格式乱码 | 编码问题 | 另存 xlsx 后校验行列数一致 |

## 9. CSV 文件的特殊处理

- 先确认分隔符（逗号/分号/制表符）与编码（UTF-8 / GBK），读错编码先转码不先洗。
- CSV 无类型信息：第一遍只做"诊断"，类型判断保守一点。
- 大 CSV（>10 万行）：先抽样 1000 行定口径，再全量跑，避免返工。

## 10. 反模式（不许这么干）

- ❌ 没备份直接改原文件
- ❌ 空值悄悄填 0 / 填"无"
- ❌ 主键重复自动删、凭感觉留
- ❌ 把公式列替换成手算的静态值
- ❌ 类型转失败的值直接丢弃
- ❌ 删了超过 10% 的行不告诉用户
- ❌ 清洗动作不记日志，"我记得我改过"

## 11. 常见问题

- **Q：表头在第 3 行，上面还有大标题，要删吗？** A：删，但把标题文字记到 README 说明页，别直接丢。
- **Q：两列看起来一样，要合并吗？** A：先问用户。看起来一样的两列常常口径不同（如"销售额"vs"回款额"）。
- **Q：清洗要保留公式吗？** A：保留。只修公式的引用错误，不许把公式拍平成静态值。
- **Q：用户说"随便洗洗就行"？** A：不行。诊断卡照出，口径照确认——"随便"的代价是返工。
- **Q：清洗时发现疑似造假的数据（如连续相同的金额）？** A：标出来告诉用户，不替用户做判断，更不许"顺手改合理"。
- **Q：多个 sheet 结构不一样，要合并吗？** A：先分别诊断，结构差异列出来给用户看；合并口径确认后再动。
- **Q：清洗完发现行数对不上？** A：停下来查：是不是删了隐藏行、有没有误删表头行。对不上不许交付。

## 12. 自检与反馈

**质检门**（每次清洗后自问）：
- [] 原文件备份存在（`.bak/` 下能找到）？
- [] 诊断卡用户确认过？
- [] 每个动作都有 opslog 记录？
- [] 行数对得上？公式列没被破坏？
- [] 审计脚本 blocker 为 0？

**标准冒烟用例**：用插件 `fixtures/` 下的脏表格跑一遍本流程，确认坏 fixture 的埋点（重复行/空值/类型混杂）都被识别和处理。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-ex-clean]`），描述：输入表特征、哪一步不符合预期、期望行为。
