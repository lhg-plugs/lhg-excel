# lhg-ex-pivot：透视与图表方法论

> 目标：让小白说出业务问题，你给出对的透视视角和对的图。核心纪律：**先定问题再选视角，先定视角再选图**。

## 1. 何时使用

- 用户说"帮我分析一下这表"但没说具体要什么 → 按第 2 步引导
- 用户明确要透视表/图表 → 直接第 3 步起
- 图表做好了自己看着别扭 → 跑第 5 步自查

## 2. 第一步：从业务问题选视角（≤2 个问题）

不要问"你想看什么图"，要问业务问题。给默认推荐，用户点头就行：

| 用户的业务问题 | 推荐透视视角 |
|---|---|
| 哪个卖得好 / 哪个部门强 | 按"类别"分组，求和/计数，降序排 |
| 这个月比上个月怎么样 | 按"月份"分组，对比环比 |
| 钱花在哪了 / 占比如何 | 按"类别"分组，看占比（饼图/堆积条形） |
| 有没有异常 | 按"类别×月份"交叉，看偏离均值的格子 |
| 趋势向上还是向下 | 按"时间"分组，折线看走势 |

问法示例："你想回答的是哪个问题？①哪个产品线贡献最大 ②各月趋势对比 ③费用占比结构（默认推荐①）"

## 3. 第二步：透视表三件套

每个透视表必须明确三个要素，缺一个就问：

1. **行**：按什么分组（类别/部门/月份，尽量 ≤15 个分组，多了先 TopN+其他）
2. **列**（可选）：第二个分组维度（做交叉表时用）
3. **值**：聚合什么（求和/计数/均值/占比），**值字段必须数值型**，文本列先转数值

规范：
- 透视表放新 sheet，命名 `透视_问题关键词`（如 `透视_产品线贡献`）。
- 保留口径说明：在透视表上方 2 行写"口径：金额=含税实收；时间=订单日期"。
- 排序：默认按值降序（找最大/最小最直观）。
- 小计/总计行保留，但标清楚。

## 4. 第三步：图表选型表（6 种够用）

| 想表达 | 用这个图 | 不用这个 |
|---|---|---|
| 排名对比（谁大谁小） | 横向条形图 | 饼图（超过 5 类别名挤成一团） |
| 占比结构 | 饼图/环形图（≤6 类） | 折线图 |
| 趋势变化 | 折线图 | 柱状图（时间点多时柱子糊） |
| 两个指标的关系 | 散点图 | 饼图 |
| 目标 vs 实际 | 柱状图+目标线 | 双饼图 |
| 分布（集中/分散） | 直方图/箱线图思路 | 平均数单数字 |

一次汇报 1-3 张图封顶，图多不如精。每张图配一句话结论（写在图下方）。

### 图表标题公式

好标题 = 时间范围 + 对比维度 + 指标，如：

- ✅ "2026 年 1-9 月各产品线销售额对比（万元）"
- ✅ "A 产品线月度销售额趋势（含税）"
- ❌ "柱状图" / "销售数据" / "Chart1"
- 标题里带单位，坐标轴就不再重复单位，避免"万元（万元）"。
- 图太小字看不清时，优先放大图而非缩小字号（汇报看的是图，不是字数）。
- 同一汇报里同类图用同一色系，不同汇报才换风格——让读者形成稳定的阅读预期。

## 5. 第四步：图表三要素自查

每张图发布前过一遍：

- [ ] **标题说人话**："各产品线 2026 年销售额对比"，不许是"Chart1"/"柱状图"
- [ ] **坐标轴有单位**：金额标"万元"、比例标"%"，不许让读者猜
- [ ] **数据标签不遮挡**：标签不压线、不重叠；类别名太长就用横向条形图
- [ ] **颜色**：同一指标一个色系；不用红绿对比表达非褒贬（色盲友好可加图案）
- [ ] **无 3D 效果**：3D 饼图/柱状图扭曲比例，一律不用
- [ ] **数据对得上**：图上的总数与透视表总数一致（随手加总验证）

## 6. 第五步：汇报版封装规范

- 图表 sheet 命名 `图表_关键词`，或直接放在透视表右侧。
- 打印友好：设置打印区域、横向、每页重复标题行。
- 数字格式：金额千分位、百分比保留 1 位小数，全表统一。

## 7. 实战 walkthrough（销售明细表示例）

输入：一张 1.2 万行的销售明细（订单号/日期/产品线/销售员/金额/数量）。

1. 业务问题："哪个产品线最赚钱？各月趋势如何？"
2. 透视 1（`透视_产品线贡献`）：行=产品线，值=金额求和+订单计数，降序。结论句："A 产品线贡献 58% 销售额。"
3. 透视 2（`透视_月度趋势`）：行=月份，列=产品线，值=金额求和。折线图一张。
4. 口径行（每个透视表上方）："口径：金额=含税实收；月份=订单日期；退货已剔除。"
5. 汇报版 sheet 顺序：README → 清洗后明细 → 透视_产品线贡献 → 透视_月度趋势 → 图表_趋势。

## 8. 多表关联时的注意事项

- 两个表按 key 关联前，先各自做 key 的唯一性检查（key 重复会导致结果膨胀）。
- 关联后行数对账：`结果行数` 应与主表行数一致（左连接），多出来就是 key 重复了。
- 关联 key 的类型必须一致（文本型订单号 vs 数值型订单号是经典坑）。

## 9. 反模式（不许这么干）

- ❌ 用户没说业务问题就直接出一堆图
- ❌ 饼图画 12 个类别
- ❌ 坐标轴从非 0 开始（截断纵轴夸大差异）还不标注
- ❌ 图表标题叫"图表 1"
- ❌ 用 3D 图、双纵轴还不说明
- ❌ 图和透视表数字对不上就交付

## 10. 配色与字体建议

- 正文：深灰（#333）11pt；表头：深底白字或浅灰底加粗。
- 强调：一个强调色（如 #1F6FEB 蓝）只用在"结论数字"上。
- 金额：千分位 + 保留 2 位小数；百分比：1 位小数。
- 跨 sheet 风格统一：表头样式、数字格式全表一致。
- 饼图每块标注"类别名+百分比"，不依赖图例猜颜色。

## 11. 打印与分享清单

- 打印区域只框图表+结论，不框整个明细。
- 页面设置：横向、缩放调整为 1 页宽、每页重复标题行。
- 发给别人前：删掉中间过程 sheet（或隐藏），只留 README+明细+透视+图表。

## 11. 常见问题

- **Q：用户就要饼图画 12 个类别怎么办？** A：先按第 4 节劝一次；坚持要就画，但把 Top5 单独再画一张小的放旁边——让他自己看到差别。
- **Q：透视表的值字段是文本，求和不了？** A：回 lhg-ex-clean 第 4 步先转数值，文本型数字不参与聚合。
- **Q：两个图用不同口径算的同一个指标？** A：不许。同一指标全表一个口径，口径写在透视表上方。

## 12. 自检与反馈

**质检门**：
- [ ] 业务问题明确了？透视三件套（行/列/值）齐了？
- [ ] 图表选型对照第 4 节选的？
- [ ] 三要素自查全过？图下有一句话结论？
- [ ] 图表数字与透视表/明细对得上？

**标准冒烟用例**：用插件 `fixtures/` 的示例表做一次"按月份+产品线"的透视与 2 张图，对照本节清单自查。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-ex-pivot]`），描述：业务问题、选的视角/图表、哪条自查没过。
