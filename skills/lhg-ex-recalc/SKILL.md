# lhg-ex-recalc：公式复算与结果抽查

> 目标：回答"AI 改完之后，数还是对的吗"。核心纪律：**机器先扫一遍（审计脚本），人再抽查一遍（心算+交叉验证）**。

## 1. 何时使用

- 清洗/透视/改公式之后、交付前 → 全流程
- 只想快速看一眼公式有没有明显问题 → 只跑第 2 步（脚本）
- 用户质疑"这个数不对" → 按第 4 步逐项排查

## 2. 第一步：跑确定性审计脚本（必做）

用你所在平台执行本地脚本的方式，在表格所在目录运行：

```
python3 <插件目录>/scripts/audit/data_audit.py --target <目录> --format text
```

脚本会做（零第三方依赖，用标准库解析 xlsx）：

- **公式错误值扫描**：找出缓存值为 `#DIV/0!`、`#N/A`、`#VALUE!`、`#REF!`、`#NAME?`、`#NUM!` 的单元格（定位到 sheet+单元格）。
- **公式复算抽查**：对 `SUM / AVERAGE / COUNT / MIN / MAX` 这类基础公式，用 Python 独立重算引用区域，与公式缓存值比对；对不上就报 blocker。**诚实说明**：复杂公式（VLOOKUP/IF 嵌套/跨表引用）脚本只做"存在性"检查，不做语义复算，这部分靠第 4 步人工抽查。

### 脚本复算支持的公式清单

| 公式 | 复算方式 | 说明 |
|---|---|---|
| SUM(区域) | Python 求和比对 | 忽略文本单元格，与 Excel 行为一致 |
| AVERAGE(区域) | Python 均值比对 | 空单元格不计入分母 |
| COUNT(区域) | 计数比对 | 只计数值单元格 |
| COUNTA(区域) | 非空计数比对 | 文本也计入 |
| MIN / MAX(区域) | 最值比对 | 忽略空值 |
| 含 `+ - * /` 的四则公式 | Python 按运算符重算 | 单元格引用取数值 |
| 其他一切公式 | 仅检查"公式存在+无错误值" | 转人工抽查，不硬算 |

复算容差：`|重算值 - 缓存值| < 0.01` 视为通过（覆盖浮点舍入）；超过则报 blocker，由人工按第 4 步排查。
缓存值过期（Excel 未重算就保存）是最常见的"对不上"原因，先让用户在 Excel 里全量重算一次再下结论。
复算抽查的结论只针对"抽到的公式"，报告里写清抽样范围，不许写成"全表公式无误"。
- **空值/重复率统计**：每列空值率、整表重复行率，超阈值报 warning。

脚本输出分 blocker / warning / nit 三级；有 blocker 时以非零退出码退出。

## 3. 第二步：分级定义

| 级别 | 定义 | 例子 | 处理 |
|---|---|---|---|
| blocker | 数可能错了 | 公式复算对不上；`#REF!` 断裂引用；合计行被误删 | 必须修好或查明原因，不许带着 blocker 交付 |
| warning | 数可能不准 | 某列空值率 45%；重复行 3%；文本型数字 | 修掉或在报告里写清影响 |
| nit | 洁癖项 | 数字格式不统一；列宽没调 | 顺手修 |

分级是死的，判断是活的：如果某条 warning 在你这个表里就是会出事，把它升成 blocker 并写理由。

## 4. 第三步：人工抽查（脚本覆盖不到的，必做）

抽查不是全量重算，而是"抓关键、抓边界"：

1. **公式列抽 5-10 个单元格**：肉眼看公式引用的区域对不对（最常见的坑：拖公式时区域没锁 `$`、插入行后区域没跟上）。
2. **心算验证**：挑 2-3 个最简单的公式行，用计算器按一遍。
3. **透视交叉验证**：透视表的总计数，手工加总 1-2 个分组核对；占比列加总是否为 100%。
4. **边界行**：第一行、最后一行、筛选后隐藏的行——公式有没有把它们漏掉或多算。
5. **合计行**：表里的"合计"是不是 `SUM(明细)`，而不是手填的数（手填的合计最容易过期）。

抽查记录进交付报告："抽查 8 个公式单元格、2 个透视分组，全部通过"——让用户看得见。

## 5. 第四步：用户质疑"数不对"时的排查清单

按顺序查，查到就停：

1. 口径：用户说的"销售额"和你算的是不是同一个口径（含税/未税、订单日期/回款日期）？
2. 范围：筛选/隐藏行有没有被公式漏掉？透视表的数据源范围包全了吗？
3. 重复：明细里有没有重复行导致 double count？
4. 空值：空值是被当 0 算了还是被跳过了？两种算法结果差多少？
5. 公式：引用区域对吗？有没有 `#REF!`？
6. 版本：用户看的是不是旧文件？你改的是不是他手里那份？

## 6. 公式常见坑位表（抽查时重点看）

| # | 坑 | 症状 | 查法 |
|---|---|---|---|
| 1 | 引用区域没锁 `$` | 下拉填充后区域漂移 | 看第 2 行和最后一行公式是否一致 |
| 2 | 插入行后区域没跟上 | 新增数据没被求和 | 对比明细行数与 SUM 区域行数 |
| 3 | 文本型数字参与求和 | SUM 结果偏小 | TYPE 检查：文本数字不参与 SUM |
| 4 | 隐藏行/筛选行 | 小计与肉眼加总对不上 | 用 SUBTOTAL 还是 SUM，口径问用户 |
| 5 | 跨表引用断裂 | `#REF!` | 脚本扫错误值全覆盖 |
| 6 | VLOOKUP 近似匹配 | 匹配到错的行 | 第 4 参数必须为 FALSE（精确匹配） |
| 7 | 除零 | `#DIV/0!` | 分母列先查空值/0 值 |
| 8 | 手填"合计" | 明细改了合计没变 | 合计单元格必须是公式 |

## 7. 抽查记录模板（写进交付报告）

```
【复算抽查记录】
- 审计脚本：data_audit.py，blocker 0 / warning 2（已处理）
- 公式复算：抽 12 个基础公式单元格，12 个通过
- 人工抽查：公式列抽 8 格（首/中/末行）、透视分组手工加总 2 组，全部一致
- 边界：首末行、隐藏行已检查
- 结论：数字可信 / 有 1 处待用户确认（列出）
```

## 8. 反模式（不许这么干）

- ❌ 跳过脚本直接说"看着没问题"
- ❌ 公式复算对不上，改脚本阈值让它通过
- ❌ 把公式替换成手算静态值"省事"
- ❌ 抽查只抽第一行（第一行通常是对的，坑都在中间和末尾）
- ❌ blocker 没清零就交付

## 8. 跨表引用专项检查

含跨表公式的表（如 `=SUM(一月!B2:B100)`），额外查：

1. 引用的 sheet 还在吗？sheet 改名是 `#REF!` 的头号来源。
2. 引用区域覆盖全了吗？新增月份 sheet 有没有被汇总公式漏掉。
3. 汇总表与各明细表口径一致吗？（含税/未税、币种）
4. 循环引用：A 表引用 B 表、B 表又引用 A 表——Excel 会报循环引用警告，不许忽略。
5. 汇总公式的"数据源清单"：把参与汇总的 sheet 名列出来，新增 sheet 时对照补。

## 9. 常见问题

- **Q：脚本报公式复算对不上，但 Excel 打开看着是对的？** A：三种可能：①缓存值过期（Excel 没重算就保存了）——以重算为准，提示用户在 Excel 里按 Ctrl+Alt+F9 全量重算；②浮点舍入——差值 <0.01 视为通过；③公式引用了脚本不支持的函数——转人工抽查。
- **Q：warning 很多，要不要全修？** A：warning 修或写豁免理由。空值率高的列如果用户说"就这样"，写进报告即可。
- **Q：用户只给了截图/图片里的表？** A：先转成 xlsx 再走流程；截图里的数字不许直接拿来算。

## 10. 自检与反馈

**质检门**：
- [ ] 审计脚本跑过？blocker 清零？
- [ ] 公式复算抽查：抽了几个、对上几个？
- [ ] 人工抽查做了吗？（公式单元格 + 透视分组 + 边界行）
- [ ] 抽查结论写进交付报告了吗？

**标准冒烟用例**：用插件 `fixtures/` 的坏表格跑脚本，确认公式复算 blocker 与错误值 warning 都被命中；好表格零 blocker。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-ex-recalc]`），描述：表特征、脚本输出、人工抽查发现、期望行为。
